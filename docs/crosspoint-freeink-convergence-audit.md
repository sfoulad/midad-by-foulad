# CrossPoint / FreeInk SDK Convergence Audit

Status: **read-only audit. No code changed, no cherry-picks, no SDK bump, no
branches/commits/PRs beyond this document, no hardware touched.** This is the
authoritative convergence checklist for Phases 1-3, per explicit instruction.
Produced from: two background research passes (CrossPoint reader-architecture
gaps; deletions/reverted-sync/workaround gaps), this session's own direct
FreeInk SDK research (`docs/freeink-sdk-modernization-audit.md`,
`docs/ota-*` docs, `docs/tls-trust-architecture.md`), and a full git-history
cherry-pick audit. All "why" evidence traces to first-party sources: PR #148's
own body, a sync resolution ledger found in this session's scratchpad, and
direct current-code inspection — not inference.

## How to read this table

- **Migrated?**: whether Midad's `develop` currently has CrossPoint/FreeInk's
  current behavior.
- **Category** (Part 3): A=Adopt now, B=Adopt in Phase 1, C=Adopt in Phase 2,
  D=Adopt in Phase 3, E=Intentional permanent difference, F=validation-blocked
  (applied as a tag on B/C/D rows, not a separate phase), G=Obsolete/resolved.
- **Validation level** (Part 6): UPSTREAM VALIDATION SUFFICIENT / MIDAD DELTA
  TESTING REQUIRED / FULL HARDWARE VALIDATION REQUIRED. Principle: do not
  reinvent CrossPoint's testing — test the Midad delta.

## Part 9 — Recommended shortest path to convergence

1. **Adopt already-tested upstream architecture where CrossPoint's own testing genuinely transfers**: items 15 (already done), 21/22 (already correctly kept as Midad's own). Nothing further needed here — these are closed.
2. **Remove duplicate Midad implementations**: item 20 (Wi-Fi auto-connect) needs a decision first — diff the two implementations before deciding whether to adopt CrossPoint's or keep Midad's; don't let it silently persist as two parallel features.
3. **Remove compatibility shims**: item 14 (3 workaround sites) falls out automatically once item 2 (SDK bump) lands — no separate work.
4. **Test only the Midad delta**: for item 2's eventual SDK bump, this audit's own commit-level validation-tier findings (item 5's `b17beee` is upstream-validated; everything else in items 5/6 needs real hardware time) should directly drive the hardware-validation checklist — don't re-derive it.
5. **Preserve real Midad differentiators**: items 1 (Dictionary), 10 (Arabic shaping), 11/12/13 (flash-size product decisions) are correctly staying different — no convergence pressure should be applied to these regardless of upstream progress.

**Concrete next steps, in order**: (a) resolve item 20's Wi-Fi decision (cheap, standalone); (b) fix the two stale docs (items 18/19, trivial); (c) decide the freeink-sdk convergence strategy for items 2/5/6/8/9/14 as one coupled project — full-bump-when-hardware-available vs. continue narrow cherry-picks — since this audit found CrossPoint's own last-released version (`v1.5.0`) still pins the SAME commit Midad does, there is no urgency pressure to bump immediately; (d) continue the already-in-progress item 17 (TLS trust) once a test device exists; (e) items 3/4 (TextSettingsActivity, reader consolidation) can be scoped as Phase 2 planning inputs whenever that phase starts.
